### 批次 H · Electron 打包（2 天）

**迁移原因（确认）**

```
起因  火绒（HipsTray/HipsDaemon）为主 + Defender SmartScreen + 国产杀软
痛点  Tauri：Rust 外壳 + 运行时自解压 → 撞「自解压+写文件」高危特征
      NSIS 安装器本身是误报高发对象
      无代码签名（证书一年数千）→ 无信誉背书
目的  产物结构接近主流 Electron 应用，吃大厂白样本信誉
```

**打包配置**

```yaml
# electron-builder.yml
appId: com.doomsdayharem.app
productName: DoomsdayHarem
# asar 保持默认（true）—— 不写这一行
files:
  - dist/**/*
  - electron/**/*
  - package.json
  - '!node_modules/**/*'      # 省 100+ MB
win:
  target:
    - target: nsis
      arch: [x64]
    - target: portable
      arch: [x64]
  artifactName: ${productName}-${version}-${arch}.${ext}
nsis:
  oneClick: false
  perMachine: false
  allowToChangeInstallationDirectory: true
  createDesktopShortcut: true
  deleteAppDataOnUninstall: false
portable:
  artifactName: ${productName}-${version}-portable.${ext}
```

**需从 Tauri 迁移**

| Tauri 侧 | Electron 侧 |
|---|---|
| `src-tauri/src/save.rs`（AES-256-GCM + HMAC） | Node `crypto` 重写 |
| Tauri FS 插件（Mod 加载） | Node `fs` |
| `tauri.conf.json` 窗口配置 | `BrowserWindow` 选项 |
| 单实例（Tauri 内置） | `requestSingleInstanceLock()`（**必须进程第一件事**） |

**参考项目踩过的坑（抄经验，不抄配置）**

| 坑 | 规避 |
|---|---|
| asar 打包 EBUSY（bd2 踩到） | 它的特例，我们保持默认 |
| `release` 目录被 Windows 锁 | 输出目录用 `dist-electron` 独立命名 |
| `shortcutName` 含 `/` 渲染乱码 | 用纯中文/英文 |
| 双开导致双托盘双缓存 | 单实例锁 |
| `node_modules` 被打进包（138MB） | `files` 显式排除 |

## 七、每批次的固定流程

```
1. 实现
2. pnpm typecheck        必须 0 错误
3. pnpm test             必须全通过
4. pnpm build:demo       必须成功
5. 删除本批次被取代的旧文件
6. 提交 + tag（版本号 +0.01）
7. 确认 diff 里「删除行数」不为 0     ← 防止再次叠加
```

**第 7 条是本方案的核心防线** —— 如果一次提交只有新增没有删除，
说明又在叠加，立即回退重做。
