# 本地模型接口设计文档

> 版本：0.6.0 · 包：`packages/llm`

## 1. 定位

模型生成是**可选增强层**，不是依赖。游戏必须在完全没有模型的情况下完整可玩。

| 能力 | 来源 |
|---|---|
| 手写剧本（DSL） | **始终可用**，主内容 |
| 模型生成文本 | 可选，设置中开启 |
| 模型不可用 | 自动降级到手写剧本，**游戏不中断** |

---

## 2. 架构

```
┌───────────────────────────────────────────────┐
│  Narrator（叙事服务）                          │
│  ├─ 缓存查找 → 命中则直接返回                  │
│  ├─ 未命中 → 调用 Provider 生成                │
│  ├─ 失败 → 指数退避重试                        │
│  └─ 仍失败 → 降级到手写剧本                    │
├───────────────────────────────────────────────┤
│  PromptBuilder（提示词）                       │
│  ├─ 强制四层结构：动作/感官/心理/对白          │
│  ├─ 注入角色关系、生理状态、道具、时空         │
│  └─ 注入前序节拍保持连贯                       │
├───────────────────────────────────────────────┤
│  LlmProvider（统一接口）                       │
│  ├─ OllamaProvider       /api/chat (NDJSON)   │
│  ├─ OpenAiCompatProvider /v1/chat/completions │
│  │   （覆盖 LM Studio / vLLM / llama.cpp）     │
│  └─ OfflineProvider      空实现，降级目标      │
├───────────────────────────────────────────────┤
│  Transport（可注入 fetch）                     │
│  └─ Node 18+ / 浏览器 / Tauri WebView 通用     │
└───────────────────────────────────────────────┘
```

---

## 3. 统一 Provider 接口

```ts
interface LlmProvider {
  readonly kind: ProviderKind;
  readonly model: string;
  readonly baseUrl: string;

  probe(): Promise<ModelStatus>;        // 健康探测
  listModels(): Promise<string[]>;      // 列出可用模型
  generate(req): Promise<GenerateResult>;         // 非流式
  stream(req): AsyncGenerator<StreamChunk>;       // 流式
}
```

### 支持的后端

| kind | 端点 | 协议 |
|---|---|---|
| `ollama` | http://127.0.0.1:11434 | 原生 `/api/chat`，NDJSON 流 |
| `lmstudio` | http://127.0.0.1:1234 | OpenAI 兼容 |
| `vllm` | http://127.0.0.1:8000 | OpenAI 兼容 |
| `llamacpp` | http://127.0.0.1:8080 | OpenAI 兼容 |
| `openai-compat` | 任意 | OpenAI 兼容 |
| `custom` | 任意 | OpenAI 兼容 |
| `offline` | — | 不生成，降级目标 |

## 4. 使用方式

### 基本用法

```ts
import { createNarrator } from "@doomsday/llm";

const narrator = createNarrator({
  kind: "ollama",
  baseUrl: "http://127.0.0.1:11434",
  model: "qwen2.5:14b"
});

const result = await narrator.narrate(
  {
    sceneId: "sister_first",
    title: "互相破处",
    tone: "压抑十年的释放",
    participants: [
      { name: "主角", title: "扶她御姐", physiology: "处女" },
      { name: "姐姐", relation: "好感 85 / 羁绊 Lv3 / 欲情 92" }
    ],
    props: ["双头龙"],
    direction: "姐姐主导",
    time: "第1天 22:00",
    location: "安全屋卧室"
  },
  scriptedScene   // 手写剧本兜底
);

result.source;   // "model" | "cache" | "scripted"
result.scene;    // 引擎可渲染的 Scene
```

### 流式

```ts
await narrator.narrateStream(ctx, (delta) => {
  process.stdout.write(delta);   // 逐块输出
}, scriptedScene);
```

### 可用性探测与自动降级

```ts
const { narrator, status } = await ensureAvailable(config, true);
if (!status.available) {
  // narrator 已自动切到 offline provider
  console.log("模型不可用，使用手写剧本：", status.error);
}
```

## 5. 缓存

| 特性 | 说明 |
|---|---|
| 键 | `model + messages + options` 的 FNV-1a 哈希 |
| 淘汰 | LRU，默认上限 256 条 |
| TTL | 可选，0 表示不过期 |
| 持久化 | `onPersist` 回调，由 app 层接入 SQLite 或文件 |
| 命中 | 直接返回，不调用模型 |

相同场景在相同状态下重播时零推理开销。

---

## 6. 降级链

```
请求生成
   ↓
缓存命中？ ──是──→ 返回（source: "cache"）
   │否
   ↓
调用模型 ──成功──→ 返回（source: "model"）
   │失败
   ↓
重试（指数退避，默认 2 次）
   │仍失败
   ↓
有手写剧本？ ──有──→ 返回剧本（source: "scripted"）+ error 字段
   │无
   ↓
抛出 LlmError
```

**关键保证**：只要调用时提供了手写剧本，就永远不会因模型问题中断游戏。

## 7. 设置

```ts
interface LlmSettings {
  enabled: boolean;              // 默认 false
  config: ProviderConfig;        // 后端 + 端点 + 模型
  generation: GenerateOptions;   // temperature / topP / maxTokens ...
  cacheSize: number;
  cacheTtlMs: number;
  stream: boolean;
  retries: number;
  maxBeats: number;
  contentFilter: "off" | "basic";
}
```

默认关闭。开启后可在 UI 中切换后端、测试连接、调参。

## 8. 与游戏其他部分的接缝

| 接口点 | 说明 |
|---|---|
| 输入 | `ScenePromptContext`（角色关系 / 生理 / 道具 / 时空 / 前序节拍） |
| 输出 | `Scene`（与手写剧本完全同构） |
| 渲染 | 交给 `text/engine.ts`，四层描写 + 四档详细度 |
| 视图 | 像素 / 插画 / Live2D 订阅同一状态机，与文本来源无关 |
| 存档 | 缓存条目可持久化到 SQLite `event_log` 或独立表 |

模型生成的场景与手写场景在数据结构上无差别，因此渲染层与存档层无需感知来源。
