### 1.2 发现的问题（4 项）

#### ✖ A-1 · 成就重名：两条都叫「初次」

```
achievements.ts:101  { id: "act_1",        name: "初次", description: "第一次亲密行为",       category: "intimacy" }
achievements.ts:152  { id: "family_first", name: "初次", description: "与家庭成员完成第一次", category: "family" }
```

- **影响**：成就列表里出现两个「初次」，玩家无法区分
- **建议**：`family_first` 改名「血脉初章」或「家人之间」，保留 `act_1` 的「初次」
- **优先级**：P3（打磨）

#### ✖ A-2 · HTML 函数重名：`bmPick` 定义两次

```
ui-prototype.html:3886  function bmPick(el, name)  ← 参数 name 未使用，只做选中高亮
ui-prototype.html:4243  function bmPick(el, cell)  ← 后定义者生效，会写入 #bm-info
```

- **影响**：3886 的版本被 4243 覆盖，是**死代码**。目前行为正确（用的是 4243），但埋了坑
- **建议**：删除 3886 的定义
- **优先级**：P3

#### ✖ A-3 · 地图出口「单向但是正确的」—— 需确认设计意图

```
双向 ✅  jc_south:south_gate        <--> jc_center:center_gate_n
双向 ✅  jc_center:north_gate       <--> jc_east:e_gate_n
单向 ⚠  beiling:mt_foot_camp  --W--> jc_south:mountain_foot
单向 ⚠  fortress_inside:ft_entry --W--> beiling:mt_fortress
```

- **实际不是 bug**：后两条是「回程」出口，去的方向由 `sub` 入口承担
  （`jc_south:mountain_foot.sub` → `beiling:mt_foot_camp`）
- 全部 8 条连接（6 exit + 2 sub）**双向配对完整**
- **但**：`exits` 与 `sub` 两套机制并存，语义重叠，容易写出真单向
- **建议**：统一为「exit 必须双向」，sub 只用于「进入子场景」
- **优先级**：P2（体验）

#### ⚠ A-4 · CSS 重复选择器 27 处 —— 大部分是刻意的

| 选择器 | 次数 | 判定 |
|---|---|---|
| `#game` | 7 | ✅ 刻意：4 个断点 + 3 个隐藏规则 |
| `#fortress-view .defgrid` | 5 | ✅ 响应式覆盖 |
| `.mlist` | 4 | ⚠ 前 2 个是主菜单多页版本，后 2 个是响应式，**语义混用** |
| `.mtitle` | 2 | ⚠ 18 行是主菜单标题，703 行是游戏内标题，**同名不同物** |
| `.mfoot` | 3 | ⚠ 同 `.mtitle` |

- **影响**：主菜单类名与游戏内类名撞车，改一处会误伤另一处
- **建议**：主菜单类名加前缀 `mm-`（`mm-title` / `mm-foot` / `mm-list`）
- **优先级**：P3

### R-1 · 后宫全员相貌身材都必须很好

**现状问题**（`systems/companions.ts` 实测罩杯分布）：

E: 1    D: 2    C: 6    B: 9    A: 2    ?: 1（AI 无实体）

| pianist | 女钢琴家 | 167 | 优雅修长，**B-cup**，手指很长 |
| pilot | 女飞行员 | 169 | 挺拔，**B-cup**，有飞行员的站姿 |

**要求**：后宫全员相貌与身材都必须是「很好」的水准。

**需要改动的四处**

1. **数据层** `systems/companions.ts`
   - `build` 字段：全部重写为「身材好」的描述，去掉 `A-cup` / `清瘦` / `疲惫`
   - 建议统一到 **C-cup 起步**，主力区间 D-E
   - `cup` 字段同步上调

2. **新字段：相貌描述**
   - 目前只有 `build`（身材），**没有相貌字段**
   - 需要新增 `face` 或 `appearance`：面容 / 发色 / 眼眸 / 气质
   - 供立绘生成与 LLM 描写使用

3. **立绘** `render/rig.ts` + 22 张程序化立绘
   - 罩杯参数影响体型渲染，需同步

4. **原型数据** `docs/ui-prototype.html`
   - `COMPANIONS` / `HERO` 的 `body` 字段同步
   - 沈清（清瘦）、雷曼（结实）也要改

**待确认的设计问题**

- 「很好」是所有人同一档，还是**分档次**（S/A/B）？
- 身高区间要不要收窄？现在 158-176cm，跨度 18cm
- 性格与外貌要不要**反差**（如修女外表清素、身材极好）？
- 体重数据（原型里是 48-62kg）要不要一并调整？

### R-2 · 装备增加「近战武器」槽

**现状问题**：

```
clothing.ts  ClothingSlot = head | face | torso | outer | legs | feet | hands
                            | underwear_top | underwear_bottom | accessory | harness
             ← 11 个槽位全部是服装，没有任何武器槽

原型 html   3038  <div class="eq-slot q-rare"><span class="esl">主武器</span>...  步枪
            3039  <div class="eq-slot q-uncommon"><span class="esl">副武器</span>... 手枪
            3239  同伴「主武器」= 消防斧
            3240  同伴「副武器」= 未装备
```

**核心矛盾**：

- 原型画了 **主武器 / 副武器** 两个槽，但**代码里一个都没有**
- 原型同伴（姐姐）拿的是**消防斧**（近战），却放在「主武器」槽
- 主角拿的是**步枪 / 手枪**（远程），也在同一组槽里

**要求**：装备增加**近战武器槽**。

**建议的槽位设计**（待确认）

```
远程：主武器（步枪/弓）  副武器（手枪）
近战：近战武器（刀/斧/棍/撬棍）   ← 新增
防护：护甲（torso 冲突？）  头盔（head 冲突？）
```

**需要改动的五处**

1. `systems/clothing.ts`
   - 新增 `WeaponSlot` 类型 或 扩展 `ClothingSlot`
   - 需要决定：武器是独立系统还是复用 clothing

2. `systems/inventory.ts`
   - 物品需要 `weaponType`（melee / ranged）、`damage`、`range`、`durability`
   - 现有武器类物品只有描述，无数值（见待办 S-5）

3. `systems/combat.ts`
   - 近战武器影响近身攻击，远程影响远程攻击
   - 需要处理「切换武器」是否消耗回合

4. `runtime/session.ts`
   - 新增 `equipWeapon` / `unequipWeapon` / `equippedWeapon`
   - 同伴也可装备（见待办 S-4）

5. `docs/ui-prototype.html`
   - `#hero-detail` 的 `h-wear` / `h-equip` 子标签增加近战槽
   - 同伴详情 `d-wear` 同步

**关联待办**：S-4 装备系统、S-5 武器数值与耐久、S-6 弹药消耗

**待确认的设计问题**

- 「近战」是**独立槽**，还是与远程**共用主手**（装备其一）？
- 徒手 / 枪托也算近战吗？
- 近战武器要不要**耐久**（斧头砍丧尸会钝）？
- 扶她对战斗有影响吗？（不变式 INV-6：扶她**不入战斗统计**，但器官不影响挥斧）
- 近战与无人机的定位关系？
