## 1. 架构总览

```
┌──────────────────────────────────────────────┐
│  apps/desktop  (Tauri 2.x 外壳)              │
│  ├─ src-tauri/  Rust：窗口/存档加密/Mod 加载 │
│  └─ src/        React：HUD/科技树/后宫/H播放器│
├──────────────────────────────────────────────┤
│  packages/core  (纯 TS 引擎，无 IO，可测试)  │
│  ├─ ECS         实体/组件/查询               │
│  ├─ systems/    生存/关系/岗位/作弊          │
│  ├─ text/       文本引擎（四层描写）+ 视图层  │
│  └─ data/       场景与配置（JSON，可 Mod）   │
├──────────────────────────────────────────────┤
│  渲染层（全部可选）：Pixel / Illustration /   │
│  Live2D —— 订阅同一 SceneViewState           │
└──────────────────────────────────────────────┘
```

**分层原则**

| 层 | 职责 | 依赖方向 |
|---|---|---|
| core | 规则、数值、状态机、文本生成 | 不依赖任何 IO / 渲染 |
| renderer | 订阅状态机输出画面 | 依赖 core 的类型 |
| app | 组装、持久化、UI | 依赖 core + renderer |

core 不引用 Phaser / React / SQLite —— 因此可在 Node 里直接跑测试。

## 2. ECS 组件定义

```ts
// packages/core/src/components.ts（已实现）

Survival     { hunger, thirst, stamina, energy, mood }   // 0-100
Lust         { value, daysSinceIntimacy, forced }        // 只升不降
Relationship { affection, loyalty, bond:1-5, role }      // 只升不降
Intimacy     { with: Record<entityId, 0-100> }           // 后宫两两
Physiology   { sex, virgin, pregnant, pregnancyProgress, fertileWindow }
Job          { id: JobId|null, bonus, daysOnJob }
Identity     { name, title, age, heightCm, tags }
AiCore       { level:2-10, hasBody, hasProjection, possessesRobot }
```

**关键约束（由测试锁定）**

| 约束 | 实现 | 测试 |
|---|---|---|
| 好感/忠诚只升不降 | `gain()` 只做加法 + clamp | `affection and loyalty only rise` |
| 拒绝不扣好感 | `refuse()` 只改欲情 | 同上 |
| 欲情只升不降 | `tickLust()` 只加 | `lust stages follow the spec` |
| 夜袭不可拒绝 | `stage === "nightRaid"` 无 refuse 分支 | 同上 |
| 后宫互交禁用怀孕型 | 规则层校验，非数据结构 | 见 §7 |

## 3. 时间与全天候

```
7 个时段，覆盖 24h 无缝：
dawn(03-06) morning(06-09) forenoon(09-12) noon(12-15)
evening(15-19) night(19-23) lateNight(23-03)
```

**全天候性爱**：`slotOf()` 仅用于**演出基调**（台词/氛围/像素背景），不参与**触发判定**。
任何时段均可发起 H —— 时段只决定「怎么说」，不决定「能不能」。

## 4. 文本引擎（成人内容第一层）

```
Scene { id, title, participants, tone, beats[] }
Beat  { id, poseKey, lines[] }          // poseKey 供像素视图切帧
Line  { layer: action|sense|mind|speech, speaker?, text }
```

**四层并进**：每个节拍同时包含动作/感官/心理/对白，不是分段罗列。

**详细度采样**：`sliceBeats()` 按 detail 均匀采样并**保留首尾**，因此
简洁模式与极详模式讲的是同一个故事，只是颗粒度不同。

| detail | 节拍数 | 目标字数 |
|---|---|---|
| brief | 3 | ~200 |
| standard | 5 | ~600 |
| **detailed（默认）** | **7** | **~1500** |
| exhaustive | 10 | 2500+ |

**视图层（全部可选）**

```ts
interface View { onBeat(state: SceneViewState): void; onSceneEnd(id): void }
SceneViewState { sceneId, beatIndex, beatId, poseKey, participants, tags }
```

像素/插画/Live2D 都实现 `View`。关闭它们时状态机照常推进，文字照常输出。

## 5. 事件脚本 DSL（规划）

场景数据目前是 JSON（`data/scenes/*.json`），后续引入条件表达式用于差分文本：

```
@scene sister_first
  when: participant("sister").virgin == true && affection >= 60
  tone: "压抑十年的释放"

  @beat push_down pose:push_down
    action: 姐姐把主角按在床沿……
    sense:  夜里的空气是凉的……
    speech(sister): 你以前不是这样的。但我还是想要你。
    mind:   十年了。她想过很多次，没有一次是这样。

  @beat sink pose:sink
    action: 她咬住下唇，猛地坐到底。
    ...
@end
```

**差分挂载**：同一 `beatId` 可挂多份文本，按条件选择：

```
@variant b2 when: lust > 80
  speech(sister): 快点……我等不了了。
@variant b2 when: bond >= 4
  speech(sister): 这次换你来。
```

解析器输出与 JSON 相同的 `Scene` 结构，引擎无感。

## 6. 存档 Schema（SQLite）

```sql
-- 存档元信息
CREATE TABLE save (
  id           INTEGER PRIMARY KEY,
  slot         TEXT NOT NULL,
  created_at   TEXT NOT NULL,
  game_day     INTEGER NOT NULL,
  game_minute  INTEGER NOT NULL,
  cheat_badge  TEXT,              -- 'CHEAT' 或 NULL
  checksum     TEXT NOT NULL      -- HMAC-SHA256
);

-- 世界状态（单行）
CREATE TABLE world (
  save_id      INTEGER PRIMARY KEY REFERENCES save(id),
  weather      TEXT,
  season       TEXT,
  flags        TEXT NOT NULL DEFAULT '{}'   -- JSON
);

-- 实体（主角 / 同伴 / AI / 机器人 / 后代）
CREATE TABLE entity (
  id           TEXT NOT NULL,
  save_id      INTEGER NOT NULL,
  kind         TEXT NOT NULL,     -- hero|companion|ai|robot|offspring
  identity     TEXT NOT NULL,     -- JSON
  physiology   TEXT NOT NULL,     -- JSON
  survival     TEXT NOT NULL,     -- JSON
  PRIMARY KEY (save_id, id)
);

-- 关系（含 AI 与后宫两两亲密度）
CREATE TABLE relationship (
  save_id      INTEGER NOT NULL,
  from_id      TEXT NOT NULL,
  to_id        TEXT NOT NULL,
  affection    REAL NOT NULL DEFAULT 0,
  loyalty      REAL NOT NULL DEFAULT 0,
  bond         INTEGER NOT NULL DEFAULT 1,
  intimacy     REAL NOT NULL DEFAULT 0,   -- from->to 方向亲密度
  lust         REAL NOT NULL DEFAULT 0,
  days_since   INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (save_id, from_id, to_id)
);

-- 岗位分配
CREATE TABLE job (
  save_id      INTEGER NOT NULL,
  entity_id    TEXT NOT NULL,
  job_id       TEXT,
  bonus        REAL NOT NULL DEFAULT 0,
  days_on_job  INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (save_id, entity_id)
);

-- 科技进度
CREATE TABLE tech (
  save_id      INTEGER NOT NULL,
  branch       TEXT NOT NULL,     -- shelter|expedition|self|defense|robot|energy|pharma|longevity
  tier         INTEGER NOT NULL,
  node_id      TEXT NOT NULL,
  unlocked     INTEGER NOT NULL DEFAULT 0,
  progress     REAL NOT NULL DEFAULT 0,
  PRIMARY KEY (save_id, branch, node_id)
);

-- 已触发的 H 场景 / 事件（用于回放库与去重）
CREATE TABLE event_log (
  save_id      INTEGER NOT NULL,
  day          INTEGER NOT NULL,
  minute       INTEGER NOT NULL,
  event_type   TEXT NOT NULL,
  scene_id     TEXT,
  payload      TEXT NOT NULL DEFAULT '{}'
);

-- 怀孕记录
CREATE TABLE pregnancy (
  save_id      INTEGER NOT NULL,
  mother_id    TEXT NOT NULL,
  father_id    TEXT NOT NULL,
  conceived_day INTEGER NOT NULL,
  due_day      INTEGER NOT NULL,
  offspring_id TEXT,
  PRIMARY KEY (save_id, mother_id, conceived_day)
);

CREATE INDEX idx_rel_from ON relationship(save_id, from_id);
CREATE INDEX idx_entity_kind ON entity(save_id, kind);
```

**加密**：Rust 侧 `save_game()` / `load_game()`，AES-256-GCM + HMAC。
DB 文件落盘前整体加密；`save.checksum` 防篡改。

## 7. 规则校验层（不变式）

以下不变式在 core 中以 `assertInvariants()` 形式提供，写入前校验：

| 不变式 | 检查 |
|---|---|
| INV-1 | 任何 `gain()` 后 affection/loyalty 不下降 |
| INV-2 | 后宫 ↔ 后宫 场景不得使用 `pregnant` 型扶她药 |
| INV-3 | 扶她药效果为临时（`expiresAt` 必须存在） |
| INV-4 | 后代 `sex` 恒为 `female` |
| INV-5 | 夜袭场景无 `refuse` 选项 |
| INV-6 | 主角 `futanari` 标志不参与战斗数值 |

## 8. 作弊器 API

```ts
interface CheatOptions { enabled; console; recordAchievements; markSave }
effectsFor(opt)  // 启用即返回 CHEAT_ALL_ON（全开）
saveBadge(opt)   // markSave 为 true 时返回 'CHEAT'
new CheatConsole(opt).exec("/god")   // 受 opt.console 单独控制
```

三项玩家自选开关（`console` / `recordAchievements` / `markSave`）与主开关
`enabled` 完全解耦，默认 `enabled=false, console=false, recordAchievements=false, markSave=true`。
