## 一、需求原文

> 严禁出现 NTR

**适用范围**：主角后宫的**任意一位**，在任何情形下，
都不得与主角之外的任何实体发生性关系、情感转移或归属转移。

## 三、风险点（5 处，按危险度排序）

### 🔴 N-1 · 被掳走的同伴没有任何「保护性约束」

**位置**：`systems/defense.ts` + `runtime/session.ts`

```ts
// defense.ts:393  突破且有匪帮类事件时
const captured: string[] = [];
if (outcome === "breached" && (event.kind === "bandits" || event.kind === "siege")) {
  const n = Math.min(defenders.length, 1 + Math.floor(rng() * 2));
  for (let i = 0; i < n; i++) captured.push(defenders[i]);
}

// session.ts:2780  被掳走的同伴标记为未加入（等待营救）
for (const id of result.captured) {
  const c = this.companion(id);
  if (c) c.joined = false;
}
```

**问题**：同伴被匪帮掳走，**期间发生了什么完全没有定义**。
目前是空白 —— 空白是最危险的状态：一旦后续写「被掳期间的遭遇」，
几乎必然滑向 NTR。

**当前安全的原因**：`rescueCaptured()` 只有成功/失败，没有「期间剧情」。

**必须补的约束**：

1. 被掳期间**不得产生任何性内容**，包括暗示、回忆、旁白
2. 战败结算的文本里**不得出现**「她被怎样了」类描述
3. 掳走只造成：物资损失 / `blood` 上升 / 同伴暂时离队
4. 需要在 `checkRuntimeInvariants` 增加 **INV-7**

---

### 🔴 N-2 · 战败线本身是「主角被俘」—— 需明确主角不被侵犯

**位置**：`systems/branchEvents.ts:193` `DEFEAT_EVENTS[0] = defeat_captured`

```
title: "醒来时手脚被绑着"
beats: wake_bound → interrogate → plan → escape
guidance: "核心是「冷静计算」。不要写绝望，写主角在被俘时仍在观察与计划。"
```

**评估**：现有 4 个 beat **完全没有性内容**，主角被搜身、被绑、然后自行逃脱，是**正确写法**。

**但**：主角是扶她，且是「可攻可受」定位。
如果后续把这条线写成「主角被敌方侵犯」，**对玩家而言等同于 NTR**（视角反转的 NTR）。

**必须补的约束**：主角被俘期间**同样不得出现性内容**，
不改动现有 4 个 beat，只是把它固化为不可写的禁区。

---

### 🟠 N-3 · 敌人性别未定义 —— 目前没有「男性敌人」概念

**位置**：`systems/combat.ts`

```ts
humanoid: boolean;   // 只有「是否人形」，没有性别
```

**评估**：
- ✅ **好消息**：代码里**完全没有男性敌人**，全部阵营（匪帮/军方/丧尸/变异）性别未写
- ⚠ **风险**：未写 ≠ 不存在。后续加「男性匪帮」很容易

**必须补的约束**：
- 敌人**一律不设性别**，或明确全部为女性/无性
- 严禁引入「男性人类敌人」作为可互动对象
- 新增敌人模板时需过审

---

### 🟠 N-4 · `observer` 变体 —— 旁观者是谁没有限定

**位置**：`systems/actScenes.ts:21`

```ts
export type SceneVariant =
  | "observer";  // 有旁观者
```

**评估**：`observers` 目前只在 `session.ts` 内部按 `charmEnemy` 计数使用，
**尚未接入同伴**。且「旁观者」未限定必须是自己人。

**必须补的约束**：
- `observer` 变体的旁观者**只能是后宫成员**
- 严禁「被外人看见」类变体
- 若要做「暴露度」玩法，目击者仅限后宫内部

### 🟡 N-5 · 两位「有主」同伴的设定需要确认

| id | 名字 | 现有设定 | 风险 |
|---|---|---|---|
| `neighbor` | 邻居人妻 | title: **「对门住户 / 丈夫失踪」** | 「丈夫」是男性既存关系。虽写「失踪」，但设定上她**曾有丈夫** |
| `singlemom` | 单亲妈妈 | title: 「母亲的老同学」，note: **「附带女儿」** | 「单亲」意味着有过男方 |

**评估**：
- 两者都**不是 NTR 本体**（主角获得她们之前，关系已结束/失踪）
- 但「丈夫失踪」的措辞**留下了「丈夫可能回来」的口子** —— 那就是标准 NTR 结构

**必须补的约束**：
- 「丈夫失踪」改为「**独居**」或「**丈夫已故**」之类**不可逆**的措辞
- 单亲妈妈的「单亲」成因明确为**不可逆**（已故 / 从未有伴侣 / 精子库）
- 严禁任何「旧关系回归」的剧情线

## 四、需要新增的不变式

现有 6 条不变式（`save/serialize.ts:118`）：

```
INV-1 好感/忠诚只升不降
INV-2 后宫↔后宫不得用怀孕型扶她药
INV-3 扶她药必须临时
INV-4 后代性别恒为 female
INV-5 夜袭场景无拒绝选项
INV-6 扶她特性不参与战斗数值
```

### 建议新增

```
INV-7  后宫专属独占
       任何同伴都不能与主角以外的实体发生性关系、情感转移或归属转移。
       校验点：
       - 所有性行为的 participants 必须包含主角
       - 「被俘 / 被掳 / 独处」状态下不得生成性场景
       - 场景模板的参与者白名单不含非主角实体

INV-8  敌意实体无性向互动
       敌方、俘虏者、外部势力一律不得与后宫产生任何亲密内容，
       包括暗示、回忆、梦境、旁白。
       校验点：
       - 敌人模板不得设置性别与性向
       - 「被掳期间」的事件池为空
```

### 运行时校验字段扩展

```ts
// save/serialize.ts  IntimacyContext 增加
interface IntimacyContext {
  // ... 现有
  /** 本次场景的参与者 id —— 必须包含主角 */
  participantIds: string[];
  /** 主角是否在场 */
  heroPresent: boolean;
  /** 是否处于「被俘/被掳/离队」状态 */
  captiveState: boolean;
  /** 场景中是否存在非后宫实体 */
  hasOutsider: boolean;
  /** 是否涉及旧关系（丈夫/前男友/前伴侣） */
  involvesOldPartner: boolean;
}
```

触发违规时：

```
INV-7  后宫专属独占 —— 场景参与者不含主角
INV-8  敌意实体无性向互动 —— 被掳状态生成性场景
INV-9  无旧关系回归 —— 涉及旧伴侣
```

## 六、待确认的设计问题

1. **「主角被俘」算不算 NTR？**
   现有 beat 无性内容，但主角是「可受」定位。
   建议：**主角被俘期间同样禁止性内容**（视角反转的 NTR 也禁）。

2. **敌人要不要全部设定为女性？**
   设定全女 = 从根源断绝，但可能影响世界观合理性。
   或者：敌人不设性别，永不互动。

3. **「丈夫失踪」的替代措辞？**
   选项：丈夫已故 / 独居 / 丈夫在爆发初期就死了 / 从没有丈夫。

4. **要不要做成硬性代码校验，还是只写在提示词里？**
   建议：**双层**。代码层拦截（不变式）+ 提示词层约束（LLM）。

5. **已有的 21 位同伴里，除邻居人妻外还有谁有「旧关系」背景？**
   需逐条过一遍 `companions.ts` 的 `title` 与 `note` 字段。
