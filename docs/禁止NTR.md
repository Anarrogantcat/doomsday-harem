# 禁止 NTR —— 需求记录与风险点排查

> 提出时间：v0.62.0（commit 7121948）
> **状态：已记录，不开工。五条铁律已拍板（L-1～L-5）。**
> 本文件同时记录「现有代码中所有可能滑向 NTR 的位置」，供后续逐条封堵。

## 一、需求原文

> 严禁出现 NTR

**适用范围**：主角后宫的**任意一位**，在任何情形下，
都不得与主角之外的任何实体发生性关系、情感转移或归属转移。

## 三、风险点（5 处，按危险度排序）

### 🔴 N-1 · 被掳走的同伴没有任何「保护性约束」

**位置**：`systems/defense.ts` + `runtime/session.ts`

```ts
// defense.ts:393  突破且有匪帮类事件时
const captured: string[] = [];
if (outcome === "breached" && (event.kind === "bandits" || event.kind === "siege")) {
  const n = Math.min(defenders.length, 1 + Math.floor(rng() * 2));
  for (let i = 0; i < n; i++) captured.push(defenders[i]);
}

// session.ts:2780  被掳走的同伴标记为未加入（等待营救）
for (const id of result.captured) {
  const c = this.companion(id);
  if (c) c.joined = false;
}
```

**问题**：同伴被匪帮掳走，**期间发生了什么完全没有定义**。
目前是空白 —— 空白是最危险的状态：一旦后续写「被掳期间的遭遇」，
几乎必然滑向 NTR。

**当前安全的原因**：`rescueCaptured()` 只有成功/失败，没有「期间剧情」。

**必须补的约束**：

1. 被掳期间**不得产生任何性内容**，包括暗示、回忆、旁白
2. 战败结算的文本里**不得出现**「她被怎样了」类描述
3. 掳走只造成：物资损失 / `blood` 上升 / 同伴暂时离队
4. 需要在 `checkRuntimeInvariants` 增加 **INV-7**

---

### 🔴 N-2 · 战败线本身是「主角被俘」—— 需明确主角不被侵犯

**位置**：`systems/branchEvents.ts:193` `DEFEAT_EVENTS[0] = defeat_captured`

```
title: "醒来时手脚被绑着"
beats: wake_bound → interrogate → plan → escape
guidance: "核心是「冷静计算」。不要写绝望，写主角在被俘时仍在观察与计划。"
```

**评估**：现有 4 个 beat **完全没有性内容**，主角被搜身、被绑、然后自行逃脱，是**正确写法**。

**但**：主角是扶她，且是「可攻可受」定位。
如果后续把这条线写成「主角被敌方侵犯」，**对玩家而言等同于 NTR**（视角反转的 NTR）。

**必须补的约束**：主角被俘期间**同样不得出现性内容**，
不改动现有 4 个 beat，只是把它固化为不可写的禁区。

---

### 🟠 N-3 · 敌人性别未定义 —— 目前没有「男性敌人」概念

**位置**：`systems/combat.ts`

```ts
humanoid: boolean;   // 只有「是否人形」，没有性别
```

**评估**：
- ✅ **好消息**：代码里**完全没有男性敌人**，全部阵营（匪帮/军方/丧尸/变异）性别未写
- ⚠ **风险**：未写 ≠ 不存在。后续加「男性匪帮」很容易

**必须补的约束**：
- 敌人**一律不设性别**，或明确全部为女性/无性
- 严禁引入「男性人类敌人」作为可互动对象
- 新增敌人模板时需过审

---

### 🟠 N-4 · `observer` 变体 —— 旁观者是谁没有限定

**位置**：`systems/actScenes.ts:21`

```ts
export type SceneVariant =
  | "observer";  // 有旁观者
```

**评估**：`observers` 目前只在 `session.ts` 内部按 `charmEnemy` 计数使用，
**尚未接入同伴**。且「旁观者」未限定必须是自己人。

**必须补的约束**：
- `observer` 变体的旁观者**只能是后宫成员**
- 严禁「被外人看见」类变体
- 若要做「暴露度」玩法，目击者仅限后宫内部

---

### 🟡 N-5 · 两位「有主」同伴的设定需要确认

| id | 名字 | 现有设定 | 风险 |
|---|---|---|---|
| `neighbor` | 邻居人妻 | title: **「对门住户 / 丈夫失踪」** | 「丈夫」是男性既存关系。虽写「失踪」，但设定上她**曾有丈夫** |
| `singlemom` | 单亲妈妈 | title: 「母亲的老同学」，note: **「附带女儿」** | 「单亲」意味着有过男方 |

**评估**：
- 两者都**不是 NTR 本体**（主角获得她们之前，关系已结束/失踪）
- 但「丈夫失踪」的措辞**留下了「丈夫可能回来」的口子** —— 那就是标准 NTR 结构

**必须补的约束**：
- 「丈夫失踪」改为「**独居**」或「**丈夫已故**」之类**不可逆**的措辞
- 单亲妈妈的「单亲」成因明确为**不可逆**（已故 / 从未有伴侣 / 精子库）
- 严禁任何「旧关系回归」的剧情线

## 四、需要新增的不变式

现有 6 条不变式（`save/serialize.ts:118`）：

```
INV-1 好感/忠诚只升不降
INV-2 后宫↔后宫不得用怀孕型扶她药
INV-3 扶她药必须临时
INV-4 后代性别恒为 female
INV-5 夜袭场景无拒绝选项
INV-6 扶她特性不参与战斗数值
```

### 建议新增

```
INV-7  后宫专属独占
       任何同伴都不能与主角以外的实体发生性关系、情感转移或归属转移。
       校验点：
       - 所有性行为的 participants 必须包含主角
       - 「被俘 / 被掳 / 独处」状态下不得生成性场景
       - 场景模板的参与者白名单不含非主角实体

INV-8  敌意实体无性向互动
       敌方、俘虏者、外部势力一律不得与后宫产生任何亲密内容，
       包括暗示、回忆、梦境、旁白。
       校验点：
       - 敌人模板不得设置性别与性向
       - 「被掳期间」的事件池为空
```

### 运行时校验字段扩展

```ts
// save/serialize.ts  IntimacyContext 增加
interface IntimacyContext {
  // ... 现有
  /** 本次场景的参与者 id —— 必须包含主角 */
  participantIds: string[];
  /** 主角是否在场 */
  heroPresent: boolean;
  /** 是否处于「被俘/被掳/离队」状态 */
  captiveState: boolean;
  /** 场景中是否存在非后宫实体 */
  hasOutsider: boolean;
  /** 是否涉及旧关系（丈夫/前男友/前伴侣） */
  involvesOldPartner: boolean;
}
```

触发违规时：

```
INV-7  后宫专属独占 —— 场景参与者不含主角
INV-8  敌意实体无性向互动 —— 被掳状态生成性场景
INV-9  无旧关系回归 —— 涉及旧伴侣
```

## 六、已确认的 4 条铁律（本轮拍板）

| 编号 | 决定 | 落地位置 |
|---|---|---|
| **L-1** | **主角被俘同样禁止性内容** | `branchEvents.ts:193` `defeat_captured` 的 guidance 加禁区声明 |
| **L-2** | **「丈夫失踪」→ 不可逆措辞**（已故 / 独居 / 爆发初期死了） | 见 6.2 的 9 处清单 |
| **L-3** | **敌人全部女性**；世界观：**末日病毒导致男性消失** | `combat.ts` 敌人模板 + 敌方剧本 + 世界观文档 |
| **L-4** | **非人妻后宫全为处女；人妻最多 3 人** | `session.ts:281` `makeCompanion` 的 `virgin` 判定 |

### 6.1 L-3 是世界观的「根」——一次性解释六处既有设计

| 既有设计 | 由 L-3 获得解释 |
|---|---|
| 敌人全是女性 | 世界上没有男性存在 |
| 邻居人妻「丈夫**已故**」 | 丈夫在病毒中死去，**不可逆** |
| 单亲妈妈的成因 | 同上，不可逆 |
| 后代**恒为女性**（INV-4） | 主角精子只带 X 染色体，全世界只剩 X |
| 主角是唯一的扶她 | 唯一具备插入能力的「男性角色」 |
| 后宫全员只对主角有性趣 | **不存在男性竞争者 → NTR 在物理上不可能** |

**结论：这是目前最强的 NTR 防线 —— 不从规则层面禁止，而是从世界观层面让 NTR 不存在。**

这条设定同时把 INV-4（后代恒女）从「魔法」变成了「遗传学必然」。

### 6.3 旧关系完整审计（21 人全查）

**结论：只有 `neighbor`（邻居人妻）一人涉及旧关系。**
其余 20 人的 `title` 与 `note` 字段**全部没有旧伴侣**。

但有两处**间接**暗示：

| 角色 | 年龄 | 状况 | 处理 |
|---|---|---|---|
| `mother` 母亲 | 45 | 累计怀孕 3 / 生产 3 / 已育 3 | **有子女，必然非处**；成因未明，需与 L-4 一起定 |
| `singlemom` 单亲妈妈 | 42 | 有 19 岁女儿 | 同上 |

这两位**不是人妻却有子女** —— 已由 **L-5** 解决：
「人妻」定义放宽为「**有过伴侣的女性**」，这两位归入该类，与邻居人妻合计**正好 3 人**。

### 6.4 L-5 · 「人妻」定义放宽（本轮拍板）

**决定：**

> **「人妻」放宽为「有过伴侣的女性」。**
> 母亲 + 单亲妈妈 + 邻居人妻 = **正好 3 人，卡在上限。**
> 此后新增同伴一律为处女，不得再有人妻 / 有过伴侣者。

**为什么这个定义能自洽：**

| 角色 | 年龄 | 子女 | 归类 | 理由 |
|---|---|---|---|---|
| `mother` 母亲 | 45 | 3 个 | ✅ 有过伴侣 | 生过 3 个孩子，必然有过伴侣 |
| `singlemom` 单亲妈妈 | 42 | 1 个女儿 | ✅ 有过伴侣 | 有 19 岁女儿 |
| `neighbor` 邻居人妻 | 35 | 0 | ✅ 有过伴侣 | 丈夫已在爆发初期去世 |
| 其余 18 人 | 18-38 | 0 | ❌ 处女 | 无伴侣史 |

**名额状态**

```
上限   3 人
已用   3 人  ← mother / singlemom / neighbor
剩余   0 人
```

**连锁约束（必须一起落地）**

1. `session.ts:281` `makeCompanion` 的 `virgin` 判定必须改为
   **按角色数据决定**，不能再是「family/mainline/side 一律 true」

   ```ts
   // 现在（错误）：21 人全部 true
   virgin: def.origin === "family" || def.origin === "mainline" || def.origin === "side"

   // 应为：由角色定义显式声明
   virgin: def.virgin ?? true
   ```

2. `companions.ts` 的 `CompanionDef` 需要新增字段：
   ```ts
   /** 是否有过伴侣（决定非处女身份） */
   hadPartner?: boolean;
   /** 是否处女（默认 true；hadPartner 为 true 时应为 false） */
   virgin?: boolean;
   ```

3. 仅这 3 人设 `hadPartner: true, virgin: false`：
   `mother` / `singlemom` / `neighbor`

4. **新增同伴时的人妻校验**：`hadPartner: true` 的角色总数**不得超过 3**，
   需要加测试锁死（见 NTR-9）

5. 母亲与单亲妈妈的**成因必须不可逆**（L-2 同源）：
   她们的伴侣同样在**爆发初期去世**，不是「失踪」、不是「离开」

**为什么不用其他三个解法：**

| 解法 | 为何不采纳 |
|---|---|
| ② 「人妻」= 已婚，母亲归「母亲」类 | 分类变复杂，且「非处 3 人」与「人妻 3 人」两套规则并存 |
| ③ 母亲生育改「领养/试管/灾前」 | 与已定的「母亲是主角处女的夺取者」剧情冲突 |
| ④ 单亲妈妈女儿改「领养」 | 女儿是**独立攻略对象**，改了会削弱角色关系 |

**L-5 与 L-4 的关系**

```
L-4  非人妻后宫全为处女；人妻最多 3 人
L-5  「人妻」= 有过伴侣的女性            ← 定义澄清
     ↓ 合并后
     有过伴侣者 ≤ 3 人，其余全部处女
```

### 6.5 L-5 拍板后的最终状态

```
有过伴侣者（非处女）    3 人   ← mother / singlemom / neighbor
                            ↑ 已达上限，此后新增同伴一律处女
处女                    18 人
```

| 结构 | 同伴不外流 / 不叛变 / 人妻名额已满（L-4 / L-5） |
| 事件 | 被掳期间事件池为空（NTR-3）；主角被俘禁性内容（L-1） |
| 提示词 | LLM 生成层加禁令（NTR-8） |
| 校验 | 新增 INV-7 / INV-8（NTR-1 / NTR-2） |
